# Nyar Garbage Collector (nyar-gc)

`nyar-gc` 是一个专为 Nyar VM 优化的、高性能、低延迟的垃圾回收器。

垃圾回收器的设计本质上是一场关于**吞吐量、停顿时间（Latency）和内存开销**的权衡。
- **没有最完美的 GC**：Java 的 G1/ZGC 追求极致的内存整理和分代效率，但付出了昂贵的写屏障和指针重定位开销。
- **只有最适合的 GC**：`nyar-gc` 的设计目标并非通用性，而是为了深度适配 Nyar VM 的 **NaN-Boxing** 架构和 Rust 的 **RAII** 模型。

## 与主流 GC 的核心差异

与 Java 等托管语言的主流 GC 不同，`nyar-gc` 选择了以下设计路径：

1. **非移动设计 (Non-moving)**：对象在分配后，其物理地址在整个生命周期内保持固定。
2. **非分代架构 (Non-generational)**：移除了新生代/老生代概念及复杂的对象晋升逻辑，转而采用基于块（Block）的统一管理。
3. **RAII + GC 整合**：托管对象在被回收时会遵循严谨的生命周期四阶段（Allocate -> Initialize -> Finalize -> Delocate），确保资源的确定性释放。

## 为何不移动、不压缩、不分代依然高性能？

虽然放弃了主流 GC 的一些“标准特性”，但 `nyar-gc` 通过以下垂直优化实现了极致性能：

### 1. NaN-Boxing 的指针零开销访问
NyarVM 使用 **NaN-Boxing** 技术将指针嵌入在 64 位浮点数的非有效位中。
- **零开销解引用**：非移动式设计允许直接在 `Value` 中存储原始指针。访问对象属性时无需通过“句柄表 (Handle Table)”或“转发指针 (Forwarding Pointer)”，避免了每次内存访问的额外延迟。
- **规避重定位开销**：如果移动对象，更新所有嵌入在浮点数位模式中的指针将带来巨大的 CPU 开销，这在解释器场景下是不可接受的。

### 2. 碰撞指针与 TLAB 的极致分配
虽然不分代，但 `nyar-gc` 依然保留了最快的分配方式：
- **块式碰撞指针**：在 [GcBlock](file:///e:/普遍优化/nyar-gc/src/lib.rs#L30) 内分配仅需简单的指针加法，性能等同于栈分配。
- **TLAB (Thread Local Allocation Buffer)**：每个线程分配独立的 64KB 本地缓冲区。绝大多数分配在 TLAB 内无锁完成，彻底规避了多线程竞争。

### 3. RAII 确定性终结 (Deterministic Finalization)
- **资源即时释放**：托管对象被回收时立即执行其 `Finalize::finalize` 逻辑。这意味着文件句柄、Socket 等非内存资源能被及时关闭，无需像 Java 那样等待不确定的 GC 扫描。
- **FFI 友好**：Rust 原生代码持有的托管指针始终有效，无需复杂的固定 (Pinning) 机制，极大提升了原生扩展的执行效率。

### 4. 低延迟增量清理
- **规避全局整理停顿**：通过增量标记（Incremental Marking），将 GC 停顿分散到多次微小的 `step()` 中，避免了移动式 GC 在压缩阶段动辄数十毫秒的全局停顿。
- **线性扫描规避碎片**：通过按对象大小分类的分配池（Size-segregated Storage）和块内线性扫描，在高频分配场景下有效维持内存紧凑性，无需昂贵的内存整理。

## 垃圾回收算法实现

### 1. 增量三色标记
为了平衡吞吐量与停顿时间，`nyar-gc` 实现了基于块管理的增量三色标记算法：
- **状态机**：白色（初始）、灰色（波面）、黑色（存活）。
- **写屏障 (Write Barriers)**：采用 Dijkstra 风格的增量屏障。在标记阶段，新写入的引用会被立即涂灰并加入标记栈，确保增量扫描的正确性。

### 2. 内存布局
- **1MB 对齐块**：内存按 1MB 粒度申请并严格对齐。
- **O(1) 元数据寻址**：任意指针 `p` 所属块的头部地址可通过 `p & !(1MB - 1)` 瞬间获取，使得写屏障几乎是零成本的。
- **动态回收**：每个块实时维护 `live_bytes`。当块内对象全部释放时，内存会自动归还给操作系统。

### 3. 现代并发支持
- **原子化状态机**：所有状态切换采用 `Acquire/Release` 内存序，支持多线程并发访问。
- **协程/延续追踪**：特别优化了对微根（Micro-roots）和多跳延续（Multi-shot Continuations）的追踪，适应代数效应等高级特性。

## 开发者指南

### 如何使类型可被安全回收？

所有托管类型必须实现 `Trace` trait：

```rust
impl Trace for MyObject {
    fn trace(&self, ctx: &mut MarkContext) {
        self.some_field.trace(ctx); // 标记内部引用的 GC 对象
    }
}
```

### 使用建议
- **善用 RAII**：利用 `Finalize` 处理非内存资源。
- **减少深度嵌套**：过长的引用链会增加标记阶段的栈深度。
- **及时解除引用**：缩小 GC 对象的生命周期有助于提升回收效率。
