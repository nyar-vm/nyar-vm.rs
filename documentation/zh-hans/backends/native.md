# Native 后端

Native 后端通过 `ProjectChomsky` 提取框架与 `Gaia` 汇编器，直接生成目标平台的机器码。它不仅仅是一个单一的后端，而是一个支持多种 CPU 架构与操作系统平台的矩阵。

## 支持的 CPU 架构

Native 后端通过对指令集的抽象，支持以下主流架构：

- **x86 系列**: 支持 32 位 (x86) 与 64 位 (x86_64) 指令集，包含常用扩展。
- **ARM 系列**: 支持 ARM32 与 ARM64 (AArch64)，适用于移动端与嵌入式设备。
- **RISC-V 系列**: 支持 RISCV32 与 RISCV64，涵盖多种标准扩展。
- **MIPS 系列**: 支持 MIPS32 与 MIPS64 架构。

## 操作系统与二进制格式 (ABI)

后端支持生成符合不同操作系统规范的二进制产物：

- **Windows (PE/COFF)**: 生成 `.exe`, `.dll`, `.obj`, `.lib` 等文件，完全兼容 Windows 系统调用与 PDB 调试信息。
- **Unix/Linux (ELF)**: 生成标准 ELF 格式文件，支持主流 Linux 发行版、BSD 以及作为 macOS 编译的中间格式。
- **裸机 (Bare Metal)**: 支持生成不依赖操作系统的原始机器码。

## GPU 与异构计算

除了传统的 CPU 后端，Native 矩阵还包含针对 GPU 的特殊发射器：

- **SPIR-V**: 针对 Vulkan 与 OpenCL 的跨平台着色器/计算格式。
- **PTX**: 针对 NVIDIA GPU 的并行线程执行架构。
- **GCN/CDNA**: 针对 AMD GPU 的指令集。

## 技术特性

- **高性能**: 无解释器开销，直接利用目标硬件的流水线、向量指令集与缓存特性。
- **细粒度成本模型**: 提取阶段可根据具体的微架构参数（如缓存大小、指令周期）选择最优的代码发射策略。
- **静态链接支持**: 可与现有的 C/C++ 静态库或动态库进行链接。
