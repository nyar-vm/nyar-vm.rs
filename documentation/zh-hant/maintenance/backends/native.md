# Native 後端評估與方案

本文檔評估了為 Valkyrie 編譯器添加原生指令集（x86, x64, arm64, riscv）支持的方案。

## 方案概覽

支持原生指令集有三種主要路徑，每種路徑的切入點和工作量各不相同。

### 方案 A：基於 Cranelift (推薦)

Cranelift 是一個高性能、跨平台的代碼生成器，完全由 Rust 編寫，旨在作為 LLVM 的輕量級替代品。

- **切入點**: **SSA (Static Single Assignment)**
- **優點**:
    - 編譯速度極快（適合 JIT 和快速 AOT）。
    - 純 Rust 實現，集成簡單。
    - 已經處理了寄存器分配、指令選擇和多種平台支持。
- **工作量**: 實現 `SsaProgram` 到 `Cranelift IR` 的轉換。

### 方案 B：基於 LLVM

LLVM 是工業界的標準，提供了最強大的優化能力。

- **切入點**: **SSA (Static Single Assignment)**
- **優點**:
    - 極佳的運行時性能。
    - 支持幾乎所有已知的硬件平台。
    - 極其成熟的生態系統。
- **缺點**:
    - 依賴笨重的 LLVM 庫（C++）。
    - 編譯時間較長。
- **工作量**: 實現 `SsaProgram` 到 `LLVM IR` 的轉換。

### 方案 C：自定義後端 (寄存器機模型)

直接在 `LIR` 基礎上編寫針對特定架構的發射器（Emitter）。

- **切入點**: **LIR (Low-level IR)**
- **優點**:
    - 零外部依賴。
    - 完全控制生成的機器碼。
    - 可以針對 Valkyrie 運行時進行深度優化（如代數效應的特殊處理）。
- **缺點**:
    - 巨大的工作量（需要為每個架構編寫寄存器分配器和指令選擇器）。
- **工作量**: 基於 `LIR` 實現針對 x64/arm64 的彙編發射器。

## 技術選型建議

### 1. 短期目標：Cranelift
作為第一個原生後端，**Cranelift** 是最佳選擇。它與 Valkyrie 的 SSA 結構高度匹配，且能夠同時滿足 AOT 和未來可能的 JIT 需求。

### 2. 長期目標：LLVM
對於追求極致性能的發布版本，可以引入 LLVM 後端作為可選組件。

### 3. 特殊需求：自定義 LIR 轉換
如果需要極致精簡的嵌入式運行時，或者現有的後端難以支持 Valkyrie 的代數效應（Algebraic Effects）和延續（Continuations），則考慮從 LIR 直接生成機器碼。

## 實施路徑

1. **第一階段 (調研)**:
   - 評估 `valkyrie-types` 中的 `SsaProgram` 是否包含 Cranelift 所需的所有語義信息。
   - 實驗性實現一個簡單的 `Ssa -> Cranelift` 轉換器，支持加法和返回。

2. **第二階段 (基礎實現)**:
   - 實現完整的類型映射。
   - 實現函數調用規約（Calling Convention）的處理。
   - 實現基本塊的線性化。

3. **第三階段 (高級特性)**:
   - 處理代數效應（可能需要特殊的棧操作或運行時支持）。
   - 實現調試信息（DWARF）生成。
