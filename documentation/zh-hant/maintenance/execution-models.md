# Nyar 執行模型

## 1. 概覽

Nyar 旨在支持多種執行環境，從高性能的生產環境到高度交互的開發環境。

## 2. 多出口後端架構 (Multi-Export Backend Architecture)

Nyar 採用**多出口後端架構**。雖然編譯器前端 (AST -> HIR -> CFG -> SSA -> LIR) 是線性下降的，但並非所有後端都必須從 LIR 開始變換。

每個 IR 層都有其獨特的結構優勢，適合對接不同的目標平台：

- **SSA (Static Single Assignment) -> LLVM IR**: 
    - LLVM 本身是基於 SSA 的。直接從 Nyar SSA 轉換可以保留最豐富的數據流信息，便於 LLVM 進行深度優化。
- **CFG (Control Flow Graph) -> WASM**: 
    - WASM 是一種結構化控制流格式。直接從 CFG 轉換更容易恢復 WebAssembly 所需的 `block`, `loop`, `if` 等結構，避免了 LIR 扁平化後昂貴的控制流恢復。
- **HIR (High-level IR) -> C / Source-to-Source**: 
    - HIR 保留了高層語法信息（如 Traits, 類型定義）。如果需要導出為 C 代碼或進行源對源翻譯，HIR 是最佳切入點。
- **LIR (Low-level IR) -> 解釋執行 / AOT**:
    - LIR 為高性能虛擬機設計，適合直接解釋執行或簡單 AOT 編譯為原生機器碼。

## 3. LIR 棧式模型決策

Nyar 的 LIR 選擇了**棧式計算機 (Stack Machine)** 模型，基於以下核心考量：

### 3.1 為什麼選擇棧式模型？

1.  **代碼生成簡單**:
    - 棧式字節碼非常容易從抽象語法樹 (AST) 或高層 IR (HIR) 生成。
    - 它消除了解釋器中複雜的寄存器分配算法（如線性掃描或圖著色），加快了編譯流水線。
2.  **指令格式緊湊**:
    - 大多數棧指令（如 `Add`, `Mul`, `Pop`）不需要操作數字段，因為它們隱式地操作棧頂。
    - 這使得字節碼文件更小，減少了指令獲取時的內存帶寬。
3.  **跨平台對齊**:
    - 許多主流虛擬機（JVM, WASM, CLR）都採用棧式架構。
    - 選擇棧式模型使得將 Nyar 的 LIR 下放到這些目標平台更加直接，無需重新發明執行邏輯。

### 3.2 棧幀管理 (Stack Frame Management)

Nyar 中的每個函數調用都會創建一個新的 `Frame`，其中包含：
- **操作數棧 (Operand Stack)**: 用於表達式求值過程中的臨時值存放。
- **局部變量表 (Locals)**: 用於存儲局部變量和參數，通過索引訪問。
- **上值 (Upvalues)**: 對外部作用域變量的引用，用於支持閉包。

這種混合方式（計算用棧 + 存儲用局部變量）在簡單性和性能之間取得了平衡。

### 4.1 解釋執行

在開發和調試階段，Nyar 使用內建虛擬機 (`nyar-vm`) 直接解釋執行 LIR。

- **優勢**:
  - **啟動快速**: 無需漫長的機器碼生成過程。
  - **熱重載**: 允許在不重新編譯整個程序的情況下替換函數。
  - **深度調試**: 解釋器可以直接訪問所有運行時狀態。

### 4.2 靜態編譯

在生產部署階段，LIR 可以透過 `nyar-aot` 進一步下放為目標機器碼（如 WASM 或原生指令）。

- **目標平台**:
  - **WebAssembly (WASM)**: 面向現代瀏覽器和服務端 WASM 運行時。
  - **原生二進制**: 通過後端生成器生成高性能機器碼（規劃中）。

## 5. 運行時特性

無論是解釋執行還是編譯執行，Nyar 都提供統一的運行時支持：

- **代數效應 (Algebraic Effects)**: 通過棧式處理器實現高效的控制流跳轉。
- **自動內存管理**: 基於垃圾回收的內存管理（視配置而定）。
- **元編程支持**: 運行時反射與動態類型檢查。
